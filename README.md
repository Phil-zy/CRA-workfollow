# CRA 工作流 Skill（V0.1）

> **原型阶段，持续迭代中。** 本仓库当前为 V0.1：固定模板的 Word/Excel 填写闭环已经验证，但“运行时理解并适配不同 DOCX 模板”的通用 AI Skill 尚未完成。请勿将其用于正式提交、签署、归档或替代 CRA 判断。

## 解决什么问题

临床监查员（CRA）在伦理申请、中心启动等工作中，经常需要将已确认的项目信息填写到结构化 Word 或 Excel 表单。手工操作易遗漏、难追溯，也容易误覆盖原始文件。

本项目探索把这类工作沉淀为一个可复用、可执行、可审计的 Skill：在授权的本地工作区中，依据已确认的规范化项目事实，生成一份**待 CRA 核对**的表单副本和独立核对清单；不覆盖原文件，不推断缺失信息，不代替人工审核。

当前实现为 [`.agents/skills/cra-fill-structured-form/SKILL.md`](.agents/skills/cra-fill-structured-form/SKILL.md)。

## V0.1 当前能做什么

V0.1 的有效能力仅限于**已验收的固定模板配置**：

- 每次处理一个获授权的 `.docx` 或 `.xlsx` 目标表单，并只读取本地规范化 `.xlsx` 项目事实。
- 对与文件 SHA-256 和结构指纹完全匹配、且已获 CRA 批准的模板配置，生成新的“待核对”表单副本。
- 生成独立 `.xlsx` 填写核对清单，逐字段记录已填写、已核对、缺失、冲突、待确认或人工保留等状态及来源。
- 保留公式、样式、打印设置、合并单元格和人工保留区域；不覆盖输入文件或既有输出。
- 对受保护、含宏、存在外部连接、配置不匹配或输入越出授权工作区的文件安全停止。
- 支持 CRA 完成人工核对后的独立核对记录与关联复验。
- 提供 Windows x64 / CPython 3.12 的项目隔离、离线依赖运行环境；当前回归覆盖 Word、Excel 和运行环境，共 25 项测试。

试点配置与样本位于 `fixtures/form-fill-pilot/` 和 `template-configs/cra-fill-structured-form/`。它们用于验证流程，不代表可直接适用于其他中心或项目的模板。

## 已知问题与边界

- **不支持通用 DOCX 模板适配。** 当前 Word 原型实质上只适配已分析的 20 行表格结构。对于新出现的段落式 DOCX（例如 55 段落、0 表格）会安全停止，不能自动生成有效映射或填写结果。
- 现有模板配置机制仍过度依赖特定版式；为每个新模板人工开发或编码映射，不符合本项目的最终目标。
- 只消费已确认的规范化事实文件；原始项目资料解析、OCR、邮件处理、事实归一化和知识库版本治理均不在 V0.1 范围内。
- 不支持批量填表，也不处理受试者源数据、直接识别信息、自动签署、发送、提交或正式归档。
- 运行环境当前固定为 Windows x64 / CPython 3.12；跨平台兼容性尚未验证。

## 下一步重构方向

目标是从“固定模板适配器”重构为可在运行时处理不同受支持结构的通用流程：

```text
来源文件提取 → 模板语义解析 → AI 字段映射 → CRA 审批 → 确定性写入 → 表单与核对清单双输出验证
```

核心要求：新模板不应要求开发人员编写专用填写逻辑或训练一套新规则；模板配置应仅作为 AI 解析结果的缓存和审计记录。完成不同 DOCX 结构的无开发适配验收前，本项目不会宣称已具备通用 AI 填表能力。

## 使用与安全原则

- 仅在 CRA 已授权的本地工作区中处理文件；运行时不连接外部服务。
- 输入不得包含受试者源数据或直接识别信息。
- 所有输出均为“待核对”草稿，最终判断、签名、提交与归档始终由 CRA 负责。
- 详细约束见 [`PRODUCT_RULES.md`](PRODUCT_RULES.md) 和 Skill 内的安全与审批规则。
