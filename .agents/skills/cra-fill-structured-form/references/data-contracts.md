# 数据契约

## 规范化项目事实

当前独立运行模式读取一个 `.xlsx` 文件：

- 第一列为事实名称，第二列为事实值。
- 空值以及“未勾选”视为缺失，不视为“否”。
- 文本编号和版本号按显示文本读取，不转换为数字。
- 当前样本中的非空值用于模拟 `confirmed` 事实。

未来知识库事实至少包含：`value`、`scope`、`status`、`source`、`source_location`、`effective_date`。当前原型不连接知识库。

## 模板配置

配置必须符合 `assets/template-config.schema.json`，并包含配置 ID、版本、状态、表单类型、模板格式、SHA-256、结构指纹、字段映射、人工保留区域和审批记录。Word 目标位置使用表格/行/列；Excel 目标位置使用工作表名称和 A1 单元格地址，合并区域必须指向左上角。

模板配置库必须独立于 Skill 目录。已启用配置不可原地修改。

## 核对清单

“字段核对”工作表每个目标字段占一行，至少包含：字段名称、目标位置、处理状态、来源值、目标原有值、未填写或冲突原因、来源文件及位置、建议 CRA 操作、CRA 最终决定。

“运行记录”工作表记录输入、输入哈希、表单输出格式、表单输出、核对清单输出、配置版本与哈希、执行时间、联网状态和授权确认。任务审计 JSON 记录两个输出的路径与 SHA-256；验证时逐行比对核对清单、审计记录和 Word/Excel 实际结果。不要复制受限数据正文。

## 人工核对记录

CRA 明确确认双输出后，不修改原待核对表单、原核对清单或执行审计。系统生成新的“CRA 核对记录”工作簿，在每个字段的 `CRA 最终决定` 中记录确认结论，并在“运行记录”中记录核对时间、核对人、核对 ID、总体结果、原清单路径及哈希。

独立人工核对审计 JSON 必须绑定执行审计、目标输入、事实输入、模板配置、表单输出、原核对清单和已核对清单的绝对路径与 SHA-256，并记录配置 ID/版本及逐字段确认结果。记录中不得复制受限数据正文。
